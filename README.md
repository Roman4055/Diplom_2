# Diplom_2
## Задание 2: Тестирование API

### Автотесты для проверки API сервиса Stellar Burgers

### Реализованные сценарии

Написаны автотесты, покрывающие ручки API:

**Создание пользователя (`POST /api/auth/register`)**
- успешная регистрация уникального пользователя — 200;
- регистрация уже существующего пользователя — 403, «User already exists»;
- регистрация с пропущенным одним из обязательных полей
  (email / password / name) — 403, «Email, password and name are required
  fields» (параметризованный тест на три варианта).

**Логин пользователя (`POST /api/auth/login`)**
- успешный логин существующего пользователя — 200, в ответе есть
  `accessToken` и `refreshToken`;
- логин с неверным логином или паролем — 401, «email or password are
  incorrect» (параметризованный тест).

**Создание заказа (`POST /api/orders`)**
- создание заказа с авторизацией и валидными ингредиентами — 200,
  `success: true`, в ответе есть номер заказа;
- создание заказа без авторизации — фактическое поведение API:
  заказ успешно создается (200), редирект на страницу логина происходит
  только в интерфейсе сервиса, а не на уровне API;
- создание заказа без ингредиентов — 400;
- создание заказа с невалидным хешем ингредиента — 500 Internal Server
  Error: сервер не обрабатывает ошибку и отвечает HTML-страницей вместо
  JSON, что зафиксировано в тесте как документирование фактического
  поведения.

### Структура проекта

- `urls.py` - константы: базовый URL и эндпоинты API
- `tokens.py` - вспомогательный класс для работы с токенами и
  формирования заголовка `Authorization`
- `methods` - пакет с методами API:
  - `user_methods.py` - регистрация, логин, удаление пользователя
  - `order_methods.py` - получение списка ингредиентов, создание заказа
- `tests` - пакет с тестами, разделенными по функциональности:
  - `conftest.py` - фикстуры: генерация уникального пользователя,
    регистрация с логином и гарантированное удаление пользователя
    после теста (в том числе при падении теста)
  - `test_user_auth.py` - тесты регистрации и логина
  - `test_create_order.py` - тесты создания заказа
- `pytest.ini` - настройки запуска pytest
- `requirements.txt` - зависимости проекта

Тестовые пользователи создаются с рандомным суффиксом в email и
удаляются после каждого теста, чтобы не засорять базу стенда.

### Запуск автотестов

**Установка зависимостей** (перед установкой активировать venv)

> `$ pip install -r requirements.txt`

**Запуск автотестов**

> `$ python -m pytest -v`

**Запуск автотестов со сбором результатов для Allure-отчета**

> `$ pytest -v --alluredir=allure-results`

**Генерация и открытие Allure-отчета**

> `$ allure serve allure-results`
